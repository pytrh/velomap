# Good morning

> Status report from the first night, when this was the only implementation.
> Paths below are relative to `spring-angular/`.

## What works (verified tonight, not just compiled)

- **`GET /api/route`**: curled with Bordeaux 44.8378,-0.5792 → 44.8600,-0.5500,
  `ROAD`: HTTP 200, 76 points, 3933 m, 963 s. `TRIATHLON` gives the identical route
  (by design). An unknown profile gives 400.
- **`GET /api/route/gpx`**: same coordinates: HTTP 200, `application/gpx+xml`,
  `Content-Disposition: attachment; filename="velomap-route.gpx"`, well-formed
  GPX 1.1 (checked with `xmllint`) with 76 `<trkpt>`.
- **Angular page**: `ng build` is clean (no errors or warnings). I also drove the
  real page in headless Chrome: OSM tiles load, two clicks place start/destination
  markers, *Compute route* draws the polyline and shows "Distance: 3.9 km",
  *Download GPX* saved a 76-point file, and changing the profile clears the old route.
- CORS for `http://localhost:4200` is set on the controller and confirmed via response headers.
- Smoke tests pass: `./mvnw test` (Spring context loads) and `npm test` (page component creates).
- The API key never appears in the logs, and `.env` is not committed.

## What doesn't work

- **`MOUNTAIN` fails with your GraphHopper key.** GraphHopper answers:
  *"For your account the profile parameter can only be one of [car, bike, foot]
  but was mtb"*. I kept `MOUNTAIN → mtb` as CLAUDE.md specifies instead of quietly
  mapping it to `bike`, because that would be a fake MTB route. The backend
  returns this as a 502 with GraphHopper's message, and the page shows it in red.
  **Your call:** to make it route on the free tier, change `case MOUNTAIN -> "mtb"`
  to `"bike"` in `RouteService.toGraphHopperProfile` (then all three are identical),
  or remove MOUNTAIN from the dropdown until you have a plan that allows `mtb`.
- `ROAD` and `TRIATHLON` are identical, as intended (TODO in `RouteService`).
- The map needs a mouse: there's no keyboard way to place points.
- If the GPX download itself fails, the page shows a generic "HTTP 502" message rather
  than GraphHopper's text (the error body arrives as a Blob). In practice it only
  runs after a successful compute, so it's unlikely.

## Decisions you should know about

1. **Moved `backend/velomap/*` up to `backend/`.** The scaffold was nested one level
   deeper than CLAUDE.md's `cd backend && ./mvnw spring-boot:run` expects. Git
   records it as renames. I deleted the untracked Initializr `HELP.md`.
2. **Spring Boot 4.1.1 → 3.5.16.** The scaffold used Boot 4, but CLAUDE.md says 3.x.
   The starters changed accordingly (`spring-boot-starter-web`, `spring-boot-starter-test`).
3. **`frontend/` was its own git repo.** The outer repo only stored a pointer to it
   (a broken submodule with no `.gitmodules`), so none of the frontend code would
   have been committed. I moved `frontend/.git` (one commit, "initial commit") to
   `.frontend-git-backup/` at the repo root, which is gitignored. The frontend is
   now ordinary files in this repo. Delete the backup once you're happy, or move it
   back to undo.
4. **`.env` loading.** Spring doesn't read `.env` by itself, so
   `application.properties` imports `../.env` (and `./.env`) as a properties file.
   The documented run command works with no `export`. A real env var still wins.
5. **GraphHopper errors → 502 with their message** (one `@ExceptionHandler` in the
   controller), so the page can say *why* instead of showing a bare 500.
6. **GPX is generated by us** (`GpxWriter`) from the same DTO, rather than by asking
   GraphHopper for GPX. That keeps one GraphHopper call shape and one conversion.
7. **Circle markers instead of Leaflet's pin icons**: pin images aren't copied by
   the Angular bundler without extra asset config.
8. The page shows **distance only** (the list said distance). The DTO also has
   `durationSeconds` if you want it shown.
9. **Commits:** both backend endpoints landed in one commit (I wrote them together
   and verified both before committing), then one for the frontend and one for the docs.
10. Untracked the committed `.DS_Store` files and added `.DS_Store` to `.gitignore`.
11. Angular side follows `frontend/.claude/CLAUDE.md` (OnPush, `inject()`, signals,
    `@if`/`@for`, labelled controls, `aria-live` status).

## Run it

Terminal 1:
```
cd ~/Dev/Velomap/spring-angular/backend && ./mvnw spring-boot:run
```

Terminal 2:
```
cd ~/Dev/Velomap/spring-angular/frontend && npm start
```

Then open http://localhost:4200, click a start, click a destination, press
*Compute route*, then *Download GPX*.

Quick API check:
```
curl "http://localhost:8080/api/route?fromLat=44.8378&fromLon=-0.5792&toLat=44.8600&toLon=-0.5500&profile=ROAD"
curl -OJ "http://localhost:8080/api/route/gpx?fromLat=44.8378&fromLon=-0.5792&toLat=44.8600&toLon=-0.5500&profile=ROAD"
```

Smoke tests: `cd backend && ./mvnw test` and `cd frontend && npm test -- --watch=false`.
